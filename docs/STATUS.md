# TokPress — Status

This is the continuation record for the project: what's implemented, how it's verified, and what's genuinely open. Read this before starting new work so effort doesn't get spent re-discovering things already settled here.

## What's implemented

- **Core pipeline**: tokenize with tiktoken's real `o200k_base` encoding (or a vocabulary you trained with `train-vocab`) via `tokenizer/tiktoken_adapter.py`'s `TiktokenTokenizer`, using the byte-exact `_encode_bytes`/`decode_bytes` pair so it round-trips arbitrary binary input, including invalid-UTF-8 like a lone `0xFF` byte → token-level LZ77 (`codec/token_lz.py`, `MIN_MATCH_LEN=3`, optionally primed with a shared cross-record buffer) → an entropy/bitstream mode selector that builds several candidates and keeps the smallest: fixed-width bit-packed raw tokens, per-record sparse rANS (with an escape symbol for the long tail), split match-metadata tables, chunked cumulative-history adaptive rANS, adaptive-split, and the `TokDict` order-0/order-1 cascade.
- **Custom vocabulary training (`train-vocab`)**: `tokenizer/bpe_trainer.py` learns a *valid*, transitively-complete byte-level BPE merge chain from a corpus and writes it as a tiktoken-format rank file; `--vocab` on any compress/decompress/pack/unpack command, and `tokenizer=` on the Python API. The trainer pre-tokenizes with the same regex tiktoken's encoder uses (tiktoken routes valid UTF-8 through `pat_str` and BPEs per piece), so the trained vocab is reproduced exactly — on a matching JSON-log domain it beats `o200k_base` (0.162 vs 0.178 on held-out records). Correctness-first: the old naive mined-vocab approach (STATUS history, commit `31b8f83`) produced a non-hierarchical piece set that could never be a real `tiktoken.Encoding`; `validate_mergeable_ranks` now enforces the chain invariant.
- **Cross-record adaptive batch mode (`compress_many`/`decompress_many` + CLI `pack`/`unpack`)**: many independent records are concatenated and compressed as one stream, so the chunked-adaptive entropy model and the LZ history span the whole batch; a `TOKB` container stores per-record byte lengths (LEB128 varint) for byte-exact record splitting. On 150 schema-homogeneous JSON records: per-record encoding inflated to ratio 1.19, the batch stream is 0.0875 (~91% saving).
- **`TokDict` (`src/tokpress/dictionary.py`)**: a trained, shared cross-record dictionary — an LZ priming buffer (concatenated training-record token streams), a baked order-0 rANS table, and order-1 (previous-token-conditioned) context tables for the top 64 contexts with ≥20 observed transitions, connected by a two-level escape cascade (context → order-0 → explicit out-of-band uint32) so any record — however novel — still encodes correctly, and which table to try depends only on the previous symbol and the dictionary's fixed metadata, never on the current symbol's value. `TokDict.train`/`.save`/`.load` persist it to a portable `.tokdict` file (magic `TKDC`). New wire mode `MODE_RANS_DICT=3` carries only an 8-byte fingerprint. Measured on real held-out JSON log records (never-trained-on): `tokpress+dict` beats every dictionary-less baseline, and the batch + dict combination closes most of the gap to zstd's matched dictionary (0.137 batch) — see `docs/VISION.md`.
- **`tokenize-stats` (`tokpress.tokenize_stats` + CLI)**: reports tokens/KB, bytes/token, order-0 and order-1 entropy, and adjacent-token mutual information I(T0;T1) — the paper's `thm:mi` quantities, now a validated intrinsic tokenizer-quality signal (Goldman et al., EMNLP 2024).
- **Component-ablation + repeated-split harness (`scripts/bench.py`)**: `TokDict.train` takes `use_priming`/`use_contexts` ablation knobs and a `priming_mode` ("cover" default / "concat" / "coverage" / "diverse") selector; `TokPressEncoder.compress(force_mode=...)` emits one specific mode's payload for isolated measurement. `run_ablations` (paper-scale split, 46 held-out records): per-record no-dict **0.8078** → baked order-0 only **0.4246** → +priming **0.2874** → +order-1 **0.2554** — the baked order-0 table is the dominant layer. `run_repeated_splits` (3 seeded 80/20 shuffles, current defaults): `tokpress+dict` **0.2543 ± 0.0016**, `tokpress+dict+batch` **0.2255 ± 0.0075**, `zstd_19+dict` **0.1973 ± 0.0003** (per-record; the gap to zstd's matched dict is stable, not split noise). `run_batch_attribution` isolates the `compress_many` gain: **without a dict the batch win is the cross-record adaptive model (paper-scale 0.8078 → 0.2620); with a dict the adaptive model adds exactly 0.0000 — the whole per-record 0.2554 → 0.2309 step is shared LZ history plus framing** (46 TOKZ headers saved vs a 101B TOKB header).
- **Cross-schema breadth (2026-08-31)**: the trained-dictionary regime now also runs on three real, non-JSON schemas (`scripts/bench.py` `run_schema_regimes`): conda package-metadata summaries (~210B, `package_metadata.jsonl`), the same packages' full metadata (median 5.3KB, `package_metadata_full.jsonl`), and API-telemetry records (~28B, `real_distinct_logs.json`). Measured per-record+dict / batch+dict / zstd-19+dict-blob: package summary **0.3936 / 0.2518 / 0.1313**, full records **0.2305 / 0.2220 / 0.1764**, API logs **1.268 (inflates) / 0.4421 / 0.1789** — `tokpress+dict+batch` beats every dictionary-less baseline on all three schemas, and batch mode rescues the high-entropy API logs. `data/bench/README.md` documents provenance + SHA-256 hashes; `scripts/regenerate_bench_data.py` verifies all 8 real_data corpora (green) and regenerates the locally-derived ones deterministically.
- **CLI**: `tokpress compress|decompress|pack|unpack|read|bench|tokenize-stats|train-dict|train-vocab|fit`, with `-o/--output`, `--dict`, `--vocab`, `--integrity`, and `--fast`. **Python API**: `compress`/`decompress`/`compress_file`/`decompress_file`/`compress_many`/`decompress_many`/`indexed_compress`/`indexed_decompress`/`indexed_read`/`IndexedBatchWriter`/`benchmark`/`tokenize_stats`, with optional `dictionary=`, `tokenizer=`, and `integrity=`.
- **Mode-byte flag/trailer features** (2026-09): the mode byte's high bits carry three opt-in/metadata flags that never fire on plain o200k streams (old streams, byte 0..8, parse unchanged -- see the wire-format section): `MODE_FLAG_EXT` marks the escape-capped layout of the pure adaptive/PPM modes; `MODE_FLAG_IDENTITY` marks a trailing 8-byte vocabulary fingerprint on every stream compressed with a non-default (custom `--vocab`) tokenizer, so decompressing against the wrong vocabulary raises instead of silently corrupting; `MODE_FLAG_INTEGRITY` marks an opt-in trailing crc32 of the input (`--integrity` / `integrity=True`, +4 bytes), so corruption, truncation, or a decode under the wrong dictionary/vocabulary fails loudly. This closes the documented "--vocab mismatch corrupts silently" and "single flipped bit corrupts undetectably" gaps.
- **Escape-capped high-vocabulary layouts** (2026-09): `MODE_RANS_ADAPTIVE` and `MODE_RANS_PPM` no longer skip records whose distinct-symbol count exceeds `RANS_M`; they escape-cap the transmitted alphabet to the `RANS_M-1` most frequent symbols with an out-of-band escape list (extended layout, byte-identical otherwise). Exposing this also flushed out two latent bugs: a `MODE_RANS_PPM_SPLIT` escape list that was built forward but then reversed (corrupting every stream with more than one literal escape), and a `BitReader` `read_bits` that could not refill when 56 < bit_count < 64 bits were buffered (breaking any 64-bit read after partial-bit reads -- unreachable while every field width was a multiple of 8). Both fixed and regression-tested at a shrunken `RANS_M`.
- **Diversity-aware priming picker** (`priming_mode="diverse"`): the COVER-style increment over `"coverage"` -- re-scan at every pick and take the record adding the most *new* frequent-token mass. Measured on the paper-scale split (46 held-out, per-record dict / batch+dict): concat 0.2554/0.2309, coverage 0.2531/0.2375, **diverse 0.2495/0.2187** (all at the 4096-token cap). `concat` stays the default: over 5 seeded shuffled 80/20 splits its batch mean beats diverse's on every schema measured (json 0.2286 vs 0.2343, small records 0.3220 vs 0.3294, package metadata 0.2675 vs 0.2703), and its per-record means are within 0.2% of diverse's -- the paper-scale single split is the one split where diverse leads. **Caveat added 2026-09 (see next entry and `docs/RESEARCH.md` Sec 2.6): this ranking was later found to reverse under a different, equally-defensible seeded-split scheme, so read it as "won under one specific sampling scheme," not settled.**
- **True zstd-COVER priming picker** (`priming_mode="cover"`, 2026-09): unlike `"coverage"`/`"diverse"` (whole-record scoring), `_priming_tokens_cover` implements the actual COVER mechanism -- score fixed-length token segments (256 tokens) by corpus-wide, log1p-dampened d-mer (8-token n-gram) frequency, greedily pick the best segment, then discount (scale by 0.3) its d-mers. First measured on 5 seeded splits it looked like a per-record-only win with `concat` still ahead on batch mode; **re-measured at 25 seeded splits (`run_priming_modes_repeated`, added to `scripts/bench.py`) it is the best-or-tied-best picker on *both* per-record and batch mode on json logs and small records, and statistically indistinguishable from the other three pickers on package metadata** (all four means within ~1 stdev there; `coverage` is now visibly the weakest picker across the board). This reverses the earlier 5-split conclusion and makes `cover` a legitimate default candidate, not just a fourth option -- see `docs/TODO.md`/`docs/RESEARCH.md` Sec 2.6 for the full table. **Promoted to the default `priming_mode` (2026-09)** on the strength of that 25-split result: `TokDict.train` now defaults to `"cover"` (CLI `--priming-mode` default likewise), `scripts/regression_golden.json` was re-baselined (synthetic `per_record_dict` 0.6790 → 0.6463, `batch_dict` 0.5730 → 0.5330), and the README/VISION headline numbers were updated. Paper-scale single split (json_heldout, 184/46): per-record `tokpress+dict` 0.2554 → **0.2537**, `tokpress+dict+batch` 0.2309 → **0.2256**; repeated-seeded 5-split means are per-record 0.2538 ± 0.0025, batch 0.2324 ± 0.0048 (batch still split-noise-dominated, consistent with the caveat above). Reproducing the 5-split measurement is also what surfaced the RNG-sensitivity caveat above: a from-scratch harness using a fresh `random.Random(i)` per split (rather than `bench.py`'s one continuously-advancing `random.Random(seed)`) reverses the `concat`-vs-`diverse` batch ranking on every schema at 5 splits -- the held-out sets (10-75 records) are too small for only 5 splits to average out that sampling noise, which is exactly why the 25-split re-measurement was needed.
- **Priming-cap default 8192 → 4096** (2026-09): `TokDict.train`'s `max_priming_tokens` default is now 4096. Measured on 5 seeded 80/20 splits across three real schemas, a larger buffer *hurts* once it outgrows the data's useful structure: every LZ match into the buffer pays for its (distance, length) symbols out of the baked tables, and those tables' mass spreads over a wider range as the buffer grows, so each match costs more bits even for identical content. Per-record dict means: json logs 0.2625 → 0.2549, package-metadata summaries 0.3885 → 0.3752, small records 0.5468 → 0.3397; batch means: json 0.2348 → 0.2286, small records 0.3679 → 0.3220, package summaries unchanged (0.2669 → 0.2675). Paper-scale single split (json_heldout, 46 held-out): per-record dict 0.2565 → 0.2554, batch 0.2286 → 0.2309 (single-split batch noise; the repeated-split batch mean improves). Only genuinely large-record corpora (past the per-record/batch crossover) were *thought* to benefit from raising the cap again (`package_metadata_full.jsonl`: 0.2305 at 4096 vs 0.2299 at 16384, single split) -- **re-checked on 15 repeated splits (2026-09) and not confirmed**: mean per-record ratio 0.2392 (4096) vs 0.2381 (16384), stdev ~0.0068, i.e. the claimed effect is about 6x smaller than one standard deviation (see `docs/TODO.md`'s "Budget sharing" item and `docs/RESEARCH.md` Sec 2.6 for the same small-held-out-set noise pattern found in the priming-*mode* comparison). The small-record 8192→4096 win above remains solid (effect size far exceeds its own split-to-split spread). The old 8192 default is what the published paper tables and `docs/README` single-split numbers were measured with; re-baseline with `python scripts/bench.py`.
- **`--fast` single-candidate mode** (2026-09): emit one pre-chosen candidate (adaptive-split) instead of the min-gate. Measured honestly: on whole-file prose (alice29.txt), ~12% faster encode at ~4% worse ratio (0.2976 -> 0.3094); on small records (<512 syms) it is near-ratio-neutral (adaptive-split wins every record there, confirming the earlier finding) and only ~5% faster -- the gate cost is not the small-record bottleneck. Available via `tokpress compress --fast` / `core.compress(fast=True)`; refused with a dictionary.
- **Self-contained ratio regression gate** (`scripts/bench_regression.py`, golden file `scripts/regression_golden.json`): deterministic synthetic corpora (no vendored data, no external compressor) measure whole-file and trained-dictionary ratios; any accidental wire-format/table/mode-selection regression now fails CI. Re-baseline intentional changes with `--update`. Runs on the nightly CI job; the PR job runs the fast test subset.
- **Decode-side structural validation (2026-09)**: the decoder now rejects a stream whose declared `uncompressed_size` does not match the bytes it actually decoded, and refuses a header whose LZ-token count is impossible for that size (every token covers >= 1 byte; the worst LZ case is 4/3 symbols/token), so a corrupt/hostile header can no longer drive a multi-billion-iteration allocation loop. `bitstream/varint.py` caps varints at 64 bits. These guard the default (no `--integrity`) path at zero byte cost. The `fast=True` single-candidate branch of `core.compress` now also honors the `integrity` trailer (it previously returned before applying it, silently disabling `--fast --integrity`).
- **API consistency + container-version validation (2026-09)**: `decompress_file`/`benchmark` now accept `tokenizer=` like the byte-level API, and the `TOKZ`/`TOKB`/`TOKBI` version bytes are validated (previously read/ignored) so an unknown container version raises instead of being misparsed.
- **Lazy batch decode + streaming unpack (2026-09)**: `iter_decompress_many` yields records one at a time (and `batch_record_count` reads the record count from the header without decoding); `decompress_many` is now `list(iter_decompress_many(...))` and the CLI `unpack` streams each record to disk as it is decoded. An indexed `TOKBI` batch is genuinely streamed record-at-a-time; a `TOKB`/`TOKZ` body still decodes in one pass because its adaptive model spans the whole batch (a real streaming *encode* would need a new container version).
- **parmar comparison harness (`scripts/bench.py`'s `run_parmar_comparison`)**: the VISION.md Sec 2 headline question -- tokens entropy-coded directly vs tokens piped through xz -- now runs as a focused table over the code/JSON/logs/many-small-records regimes parmar left untested, with a per-regime winner and an honest verdict. Measured on the vendored corpora: token-direct wins prose (0.2976 vs 0.3184) and isolated per-record small records (0.8064 vs 0.8468); tokens->xz wins whole-file code/JSON/logs (e.g. logs 0.1916 vs 0.1979) and the concatenated blob, so the honest answer is "not on whole-file code/JSON/logs" -- the per-record win only appears once a shared `TokDict` is trained (0.3609 vs 0.8428 per-record).
- **Test suite**: 124 tests covering bitstream and rANS roundtrips (incl. single-symbol-alphabet edge case), token-level LZ77 roundtrip, byte-exact tokenizer roundtrip on arbitrary binary, full codec roundtrips across payload shapes, `TokDict` training/save/load/escape-cascade roundtrips (incl. the ablation knobs and priming modes), batch/indexed-batch roundtrips, the BPE trainer (chain validity, determinism, tiktoken-agreement, rank-file roundtrip), custom-vocab codec roundtrips, the identity-stamp / integrity-trailer paths (wrong vocab raises; flipped bits raise), escape-capped adaptive/PPM at a shrunken `RANS_M`, `tokenize_stats` invariants, and black-box package/CLI tests. Heavy large-payload tests are marked `@pytest.mark.slow` (excluded from `make test-quick` and the PR CI job).

## Wire format (quick reference)

Single-record streams: magic `"TOKZ"` (4B) + version(1B)=1 + `mode`(1B) + `uncompressed_size`(u32 LE), then a mode-specific payload.

- `mode` (low 5 bits after masking off the flag bits): 0=raw tokens (fixed-width bit-packed), 1=per-record sparse rANS (escape symbol for the tail beyond `RANS_M-1`), 2=empty-input fallback, 3=rANS against a pre-trained out-of-band `TokDict` (8-byte fingerprint + escape list + rANS stream, no per-record freq table), 4=chunked cumulative-history adaptive rANS, 5=split match-metadata tables, 6=adaptive-split, 7=per-record PPM order-1 cascade, 8=PPM-split.
- Mode-byte flag bits (mask `0x1F` to recover the mode): `0x20` (`MODE_FLAG_EXT`) = the adaptive/PPM payload carries an out-of-band escape list (escape-capped alphabet); `0x40` (`MODE_FLAG_IDENTITY`) = an 8-byte vocabulary fingerprint trailer follows the payload; `0x80` (`MODE_FLAG_INTEGRITY`) = a 4-byte crc32 trailer follows the payload. Trailer order when both: fingerprint then crc32. The encoder ORs these into the mode byte of the winning stream only; plain o200k streams carry none, so old streams (byte <= 8) parse unchanged.
- Active-symbol-id lists are sorted, delta-encoded, and varint-packed (`bitstream/varint.py`) rather than fixed 4 bytes/symbol.
- Batch streams: magic `"TOKB"` (4B) + version(1B)=1 + n_records(u32 LE) + per-record length (LEB128 varint) + one single-record `TOKZ` stream of the concatenated records. Indexed batches: magic `"TOKBI"` + version + n_records + body_size + per-record u32 byte offsets + concatenated per-record `TOKZ` streams.

`o200k_base`'s ~200k-token vocabulary needs wide (32-bit) alphabet-size/sym-id fields; a custom trained vocab uses the same wide regime.

Full field-by-field layout lives in the module docstrings at the top of `src/tokpress/codec/encoder.py` (source of truth) and `src/tokpress/codec/decoder.py` (must mirror it exactly).

## Known limitations / open items

- **Without a trained `TokDict`, there is still no shared cross-record dictionary.** Every record pays the full per-record sparse-rANS or bit-packed cost; small or non-repetitive records can come out larger than the input (measured: a 70-byte JSON sample compressed to 81 bytes). `TokDict` fixes this for the many-small-homogeneous-records regime when you have representative training data, and the `compress_many` batch mode fixes it even without a dictionary (one adaptive stream over the batch).
- **`TokDict`'s dictionary trainer is still simpler than zstd's.** The priming constructions (`cover` default / `concat` / `coverage` / `diverse`) and count-based tables are not zstd's suffix-array-based `--train` (COVER/FastCover). This is why `tokpress+dict` still loses to zstd's matched dictionary, though the batch+dict combination closes most of the per-record gap (paper-scale batch+dict ~0.22 vs zstd's 0.137). A wrong-schema dictionary buys nothing over no dictionary at all (cross-schema experiment, Appendix B of the paper).
- **Throughput is still pure-Python and not optimized end-to-end.** `--fast` cuts whole-file encode time ~12% at ~4% ratio cost; the remaining options are mode gating with a much tighter per-mode size bound (measured: the zero-words structural bound is a -0.2% wash) and the native port (rANS + LZ with multi-state interleaving). Compress is far slower than decompress in the target regime because the encoder builds several candidates per record; decompression runs only the mode chosen.
- **Streaming batch I/O is partial.** `iter_decompress_many`/`unpack` now yield/write records one at a time, and a `TOKBI` indexed batch decodes record-at-a-time; but a `TOKB`/`TOKZ` body is still decoded in one pass (its adaptive model and LZ history span the batch) and `compress_many` still concatenates the whole batch to tokenize/encode it. A true streaming *encode* (bounded memory, no full concatenation) needs a new container version; `IndexedBatchWriter`/`pack --indexed` remains the bounded-memory writer today.
- **A custom vocab doesn't beat `o200k_base` on every domain.** It wins on a matching, schema-homogeneous domain when records are compressed independently *without* a dictionary -- a domain vocab (byte-BPE or SentencePiece) cuts the per-record header/alphabet cost, which dominates tiny records (measured on json_heldout: 0.6375 for a 4k byte-BPE vs 0.8078 for `o200k_base` per-record no-dict). Once a trained `TokDict` amortizes the alphabet across records the positions reverse (0.3106 vs 0.2565): the dictionary supplies the domain structure, so `o200k_base`'s richer, better-tuned token stream then wins (SentencePiece BPE/unigram lose the same way, 0.3225/0.2871 per-record+dict). On general or mismatched text, `o200k_base`'s far larger vocabulary wins. The trainer is also O(num_merges × corpus size), so use `--max-bytes` to sample (default 256 KB).
- **`--fast` is a throughput knob, not a ratio one.** On records under ~512 symbols adaptive-split wins the min-gate anyway, so `--fast` is ratio-neutral there and only ~5% faster; on larger records it trades ~4% ratio for ~12% encode time. It refuses `--dict` because it skips the dictionary candidate.
- **Integrity is opt-in and fingerprints are non-cryptographic.** `--integrity` guards against corruption and wrong-model decode at +4 bytes/stream; without it, a flipped bit can still corrupt output undetectably (paper Appendix E -- compress-then-AEAD whenever confidentiality or untampered integrity is required). The 8-byte vocabulary stamp detects *wrong-vocabulary* use, and the 8-byte `TokDict` fingerprint rejects wrong dictionaries; neither is a checksum of the plaintext.
- **The encoder still builds all applicable candidates per record**, which dominates throughput on large files; the measured cheap gates (length-gate adaptive-split, `array('I')` decode LUT, zero-words early exit) all lost or were washes.

## Reproducibility, packaging, and release

- **Licensed Apache-2.0** (`LICENSE`), and `pyproject.toml` now carries the license, readme, classifiers, authors, and URLs. Version is still `0.1.0`, unreleased and untagged.
- **docs/ is tracked** (STATUS/TODO/VISION + `tokpress.tex` and `tokpress.pdf`); LaTeX build by-products stay gitignored. `make paper` rebuilds `docs/tokpress.pdf` from `docs/tokpress.tex` (needs latexmk); the paper's TeX source is the reproducibility record for the report.
- **Bench corpora remain gitignored** (they live in the working tree; `data/bench/README.md` documents provenance + SHA-256, and `scripts/regenerate_bench_data.py` verifies/regenerates them). CI uses the self-contained `scripts/bench_regression.py` gate instead.
- **CI** (`.github/workflows/ci.yml`): the PR/push job runs ruff lint + format check + the fast test subset (`-m "not slow"`); the nightly job runs the full suite, the ratio regression gate, and the real bench harness (skipping corpora absent from CI).
- **`make` targets**: `test` (full), `test-quick` (excludes `@slow`), `bench`, `regression`, `paper`, plus the existing lint/format/check ones.

## Suggested next steps (not started)

- Streaming `compress_many` (read/write records incrementally, low memory) and/or random-access batch decode over a single adaptive stream. Decode-side laziness landed (`iter_decompress_many`, streaming `unpack`, `batch_record_count`); the encode side still needs a new container version because the adaptive entropy model spans the whole batch. `TOKBI` gives per-record random access over self-contained per-record streams.
- ~~A schema-adaptive priming budget for past-crossover large-record corpora~~ -- investigated (2026-09) and not pursued: the claimed large-record effect (`package_metadata_full.jsonl` 0.2305 -> 0.2299 at cap 16384) did not survive a 15-seeded-split repeated measurement (see `docs/TODO.md`'s "Budget sharing" item). Budget sharing between the priming buffer and the order-1 context tables (both compete for the same training signal) remains open and untested.
- Profile candidate-building overhead further and gate modes by a tighter per-mode size bound, or go native (rANS + LZ with multi-state interleaving) -- the research idea is established and does not change with the implementation language.
- Cut and tag a real 0.1.0 once the remaining footgun documentation is settled (the two footguns -- private `tiktoken._encode_bytes`; `--vocab` mismatch -- are now guarded by the identity stamp, but the private-API dependency remains).
